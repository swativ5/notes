# RSA (Rivest-Shamir-Adleman) Algorithm
- encrypt a message without need to share a secret key
- used for public key encryption & digital signatures
- based on the difficulty of factoring large integers

- user A can send an encrypted message to user B without sharing a secret key
- user A encrypts the message using user B's public key
- user B decrypts the message using their private key

- it can also be used to sign a message, A can sign a message using his private key and B can verify the signature using A's public key

- Features:
    - popular exponentiation in a finite field over integers including prime numbers
    - integers used are sufficiently large to make factoring difficult
    - two sets of keys: public key (e, n) and private key (d, n)

## Key Generation
1. Choose p, q such that p and q are large prime numbers
2. Compute n = p * q
3. Compute φ(n) = (p - 1)(q - 1)
4. Choose e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1
5. Compute d such that d ≡ e^(-1) mod φ(n)
- public key(KU): (e, n)
- private key(KR): (d, n)

## Encryption
- Plaintext message is converted to an integer M such that 0 ≤ M < n
- Ciphertext C is computed as C ≡ M^e mod n

## Decryption
- Ciphertext C is decrypted to plaintext M using the private key as M ≡ C^d mod n

## Digital Signatures using RSA
- Generally D_kpvt(E_kpub(M)) = M for confidentiality
- RSA also has the property that D_kpub(E_kpvt(M)) = M for signing and verification
- Since the text can also be encrypted with kpvt and decrypted with kpub, the sender can sign a message by encrypting it with their private key. The recipient can verify the signature by decrypting it with the sender's public key. If the decrypted message matches the original message, the signature is valid.

### Attacks on RSA
- Brute force - try all possible keys
- Mathematicals attacks - factor n, calculate φ(n)
- Timing attacks - use the running time of the algorithm to determine d, the decryption key
