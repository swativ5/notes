# Authentication Protocols and Services

Authentication Protocols:
- Mutual Authentication Protocols:
    - enable both parties to verify each other's identity.
- One-Way Authentication Protocols:
    - only one party verifies the identity of the other.

## Mutual Authentication Protocols
- issues about authenticated key exchange:
    - confidentiality require secret (1 key) or public keys (2 keys+).
    - timeliness: the key should be fresh to prevent replay attacks.
- GONG93 lists the following examples of replay attacks:
    - simple replay: opponent simply copies the message and replays it later
    - repetition can be logged: opponent can replay a timestamped message within the valid time window, but the system can detect it by logging the message and checking for duplicates.
    - repetition that cannot be detected: the original message could have been suppressed and thus did not arrive at the destination, so the opponent can replay it later without detection.
    - backward replay without modification: replay back to the message sender
- one approach to coping with replay attacks is to attach a sequence number to each message, and the receiver can check if the sequence number is in order. difficult to store and keep track of sequence numbers for all messages.
- other general approaches to prevent replay attacks include:
    - using timestamps: clocks among various participants be synchronized, and the receiver can check if the timestamp is within an acceptable time window.
    - challenge/response (nonce): the receiver sends a random number (nonce) to the sender, and the sender must include this nonce in its response, proving that it is responding to the current challenge and not replaying an old message.

## Symmetric encryption approaches:
- a two level hierarchy or symmetric encryption keys can be used to provide confidentialtity for communication
    - use of a trusted key distribution center (KDC) to manage and distribute keys securely.
    - each party shares a secret key, know as a master key with the KDC, and the KDC can generate session keys for communication between parties.
    - the KDC is responsible for generating keys to be used for a short time over a connection known as session keys, and distributing them securely to the parties involved in the communication.
- working:
    - A -> KDC (IDA, IDB, N1)
    - KDC -> A (EKA(KS, IDB, N1, EKB(KS, IDA)))
    - A -> B (EKB(KS, IDA))
    - B -> A (EKS(N2))
    - A -> B (EKS(f(N2)))

- improves in neum93a
    - A -> B (IDA, NA)
    - B -> KDC (IDB, NB, EKB(IDA, NA, TB))
    - KDC -> A (EKA(IDB, NA, KS, TB), EKB(IDA, KS, TB), NB)
    - A -> B (EKB(IDA, KS, TB), EKB(NB))

- public key
    - A -> AS (IDA, IDB)
    - AS -> A (...)
    - A -> B (EKB(KS, IDA))

- Kerberos:
    - a widely used authentication protocol that uses symmetric key cryptography and a trusted third party (KDC) to provide secure authentication and communication.
    - it provides mutual authentication, where both the client and the server verify each other's identity, and it also supports single sign-on (SSO) capabilities, allowing users to authenticate once and access multiple services without needing to re-enter credentials.
    - in a work station, if a user wants access services on a server, whether to permit or restrict the request is decided by the server with the help of kerberos

# Secure/Multipurpose Internet Mail Extensions (S/MIME)
- security enhancement to MIME email
    - original internet rfc822 email was text only, and MIME allows for multimedia content and attachments.
    - with encoding of binary data to textual form
    - it gives the folowing:
        - secrecy: only intended recipient can read the message
        - authentication: the recipient can verify the sender's identity
        - integrity: the recipient can verify that the message has not been altered in transit
- public key certificate:
    - it contains a person's name, that person's public key, and the name of the certificate authority (CA) that issued the certificate and digital signature of the CA, using their private key
