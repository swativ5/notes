# Feature Dectection & Matching

- Feature Detection algorithms:
    - Identufy interesting, unique descriptive features to detect the objects.
    - Match them and recognize the objects
    - Applications:
        - Image Stiching: align the two images so that they can be seamelessly stiched into a composite mosaic
        - Object recognition: Identifying specific objects within an image by comparing extracted features to a know database of object features
        - Image registration: aligning two or more images if the same scene taken at different times, angles, or sensors (used in medical imaging, remote sensing, computer vision and robotics)
        - 3D construction: to establish a dense set of correspondences so that a 3D model can be constructed or an in-between view can be generated
        - Object tracking: object tracking, feature detection & matching is used to identify and lcate key points on an object across multiple frames

- Feature: a piece of informationw which is relevant for solving the computational task related to a certain application
    - Main categories:
        - Key point/interest point/ corner featues: peaks, corner. appearance of patch of pixels surrounding the point location
        - Edges (object boundaries): matched based on their orientation and local appearance (edge profiles) and can also be good indicators of object boundaries and occlusion events in image sequences

- Main components of Feature detection and matching
    - Identify the interest point
        - point at which the direction of the boundary of the object changes abruptly.
        - properties:
            - well defined position or well localised
            - stable under local and global perturbations in teh image domain
            - should provide efficient detection
                - interest point has rich image content within local window
        - possible appriaches:
            - based on the brightness of an image
            -based on boundary extraction
        - Algorithm for identification of interest point:
            - Harris Corner detector
            - Scale Invariant Feature Transform - SIFT
            - Speeded Up Robust Features - SURF
            - Features from Accelerated Segment test - FAST
            - Oriented FAST and Roatated Brief - ORB
    - Decription: the local appearance around each feature point is decribed in some way that is invariant under changes in illumination, translation, scale and in-plane rotation
        - gives descriptor vector for each interest point
        - Feature descriptor:
            - an algoritm whicht akes an image and outputs feature descriptors/ feature vectors
            - Decriptor classes:
                - Local Descriptor: Local decriptors cature features from specific regions or points within an image. they focus on small patches of images and describe them in a way that is invariant to certain transformations
                - GLobal decriptor: summarize the entire image as a single feature bector, capturing overall characteristics rather than local deatils. like color histrogram which applied to the whole image
                - Algorithms used:
                    - SIFT, SURF, BRISK (Binary Robust Invariant Scalabe Keypoints,), BRIEF (BInary Robust Independent Feature...), ORB
    - Matching: descriptors are compared across the images to identify similar featues
        - set of pairs of matching features
        - task of establishing correspondences betwenn two images of the same scene/ object

## SIFT Detector and Feature Descriptor
 Scale Invariant Feature Transform - SIFT

- used for image alignment and 2D object recognition
- Extracting distinct inavriant features
    - correctly matched against a large DB of features of many images
- invariance to image scale and rotation
- robustness to 
    - affine distortion
    - change in 3D viewpoint
    - addition of noise
    - change in illumination
- Advantages:
    - locality: features are local, so robust to occlusion and clutter
    - distinctiveness: individual features can be matched to a large dn
    - quantity: many features can be generated or even small objects
    - efficiency: close to real-time performance
- Main steps:
    - Detecting interest points:
        - edges, corners, peaks
        - detect blobs, pathes with a local appearance (blobs of different sizes)
    - Extracting feature descriptors/ Signature for matching
- Interest points:
    - Remove the variations - size & orientation
    - Remove the points that are not interesting - not unique or distinctive
- Attribute of a good feature point:
    - Has rich image content (brightness variation) within a local window
    - Well defined position (well localised)
    - Well defined representation (stable under local and global perturbations in the image domain)
    - Should be invariant to image transformations (scale, rotation, affine transformation)
    - Should be invariant to lighting changes
- Blobs - local interesting appearance - are interest points?
    - a blob is a region of an image that differes from its surrounding area in color, brightness, or other properties
        - nomralize - size
        - local appearance - pattern
        - well defined position - have fixed position
    - blobs as interest points are better than edges or lines
- Blob detection:
    - Given an image (x, y) and sigma as size of the block
    - Convolve the image using Normalized Laplacian of Gaussian (LoG) filter at different scales (sigma)
    - Find (x*, y*, sigma*)
    - Scale space: stack created by filtering an image with Gaussians of different scales (sigma)
        - S(x, y, sigma) = n(x, y, sigma) * I(x, y)
    - Increasing the sigma, higher scale, lower resolution, more blurring
    - Select sigma such that: sigma_k = k * sigma_0, where k is a constant multiplicative factor
    - Difference of Gaussian (DoG) is an approximation of the Laplacian of Gaussian (LoG) and is computationally more efficient
        - DoG(x, y, sigma) = S(x, y, k * sigma) - S(x, y, sigma)
    - Find local extrema in the DoG space (x, y, sigma)
    - Thresholding: remove low contrast points and edge responses
- Scale invariance:
    - once detected the interest points - normalize/scaale up one to match the size of the other
    - different scale
    - different peaks
- Assign Orientation (Make Blobs Rotation Invariant):
    - for each blob region: computete the gradient magnitude and orientation at each pixel in a neighborhood around the interest point
    - create a histogram (8 bins or 36 bins) 0 to 360 degrees  - divided as 45 degree range bins or 10 degree range bins of gradient orientations, weighted by their magnitudes, and find the dominant orientation(s)
    - now each blob has Position (x, y), Scale (sigma) and Orientation (theta) - making it invariant to rotation and scale changes
- Build Descriptor (Describe blob appearance)
    - before that use the principal orientation of a blog and undo the image for the patch/blob to make it rotation invariant
        - we rotate the local patch by -theta0 so that the dominant direction becomes 0 degree.
        - divide the rotated patch into 4x4 sub-regions and compute a histogram of gradient orientations (8 bins) for each sub-region, weighted by their magnitudes
        - concatenate the histograms of all 16 sub-regions to form a 128-dimensional feature descriptor for the blob
    - for example,
        - blob 1 => orientation = 30 degree
        - blob 2 => orientation = 75 degree
        - blob 3 => orientation = -10 degree
        - then decriptor 1 is built in a frame roatated by -30 degree, descriptor 2 is built in a frame rotated by -75 degree and descriptor 3 is built in a frame rotated by +10 degree
        - this way, the descriptors are invariant to rotation and can be matched across images with different orientations
- Matching
    - use the histogram as the descriptor/ signature for tmatching as already they are scale invariant and rotation invariant and brightness invariant (as magnitude is ignored)

Comparaing SIFT Descriptors
- like comparing two arrays of data
- let H1(k) and H2(k) be two arrays of length N
- the euclidean distance between the two arrays is given by:
    - d(H1, H2) = sqrt(sum((H1(k) - H2(k))^2))
    - the smaller the distance, the more similar the two descriptors are
    - if d == 0, then the two descriptors are identical
- Normalized coorelation
- let H1(k) and H2(k) be two arrays of length N
- the normalized correlation between the two arrays is given by:
    - r(H1, H2) = (sum(H1(k) * H2(k))) / (sqrt(sum(H1(k)^2)) * sqrt(sum(H2(k)^2)))
    - the value of r ranges from -1 to 1, where 1 indicates perfect positive correlation, -1 indicates perfect inverse correlation, and 0 indicates no correlation
    - the higher the value of r, the more similar the two descriptors are
- Intersection (overlap)
- let H1(k) and H2(k) be two arrays of length N
- the intersection between the two arrays is given by:
    - d(H1, H2) = sum(min(H1(k), H2(k)))
    - the higher the value of d, the more similar the two descriptors are
- Matching all blobs:
    - each blob in image 1 is compared against all blobs in image 2, and the closest descriptor (passing Lowe ratio test) is selected as the match
- in sift mathcing, the ratio test (Lowe's ratio test) is a technique used to filter out false matches when comparing feature descriptors. It is based on the idea that a good match should be significantly better than the second-best match. The ratio test is defined as follows:
    - For each feature descriptor in image 1, find the two closest descriptors in image 2 (the best match and the second-best match) based on a distance metric (e.g., Euclidean distance).
    - Compute the ratio of the distance of the best match to the distance of the second-best match: ratio = d(best_match) / d(second_best_match)
    - If the ratio is below a certain threshold (commonly set to 0.75), then the best match is considered a valid match; otherwise, it is rejected as a false match.

- the sift undergoes the final geometric verification step, where the matched features are used to estimate a geometric transformation (e.g., homography) between the two images. This step helps to further filter out false matches and ensure that the remaining matches are consistent with the estimated transformation.
